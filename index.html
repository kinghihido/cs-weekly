01 Week 01 · How Computers Run Your Code

你写的代码，电脑是怎么跑起来的？

你让 AI 写过 Python 小脚本，双击运行，屏幕上就有了结果 —— 但中间发生了什么，像被藏进了黑盒子。 这期我们把盒子掀开一角：CPU、内存、硬盘是怎么分工的，一行 print("hello") 要经过哪些站才能变成屏幕上的字。 不需要数学，不需要算法，只需要你会开机。

00

为什么要懂这个

先说清楚定位：这一系列不打算把你培养成程序员。 写算法、啃框架、刷题 —— 那些 AI 干得比你快，也没必要再练。 但有一件事 AI 替代不了：你得能看懂电脑在干什么，才能把问题说清楚、把 AI 给的东西用好。

而看懂的第一步，不是什么高深理论，是三样你天天在摸的硬件，和一条从键盘到屏幕的路。 读懂这期，你就能回答这些以前只能背口诀的问题：

  • 为什么内存不够电脑会卡，硬盘不够只是装不下？
  • 为什么程序要「加载」几秒才能打开，关机再开还要重新加载？
  • 任务管理器里 CPU 100% 和磁盘 100%，是完全不同的两种病，怎么分？
所有性能问题，本质上都是某一种资源在排队。学会看「谁在排队」，你就入门了。
01

硬件三巨头：大脑、草稿纸、记事本

把一台电脑砍到最简，只剩三个干活的角色：

部件角色特点断电后
CPU大脑：负责「算」每秒几十亿次运算，但几乎什么都不记，算完就忘—
内存（RAM）草稿纸：放「正在用」的东西速度极快，CPU 随取随用，但容量有限（常见 8~32 GB）全部清空
硬盘（SSD）仓库：放「所有」东西容量大（几百 GB 到几 TB），断电不丢，但慢完好保存

还有两个配角：显卡（GPU，专门负责「画」屏幕和算图形，AI 训练也用它）和主板（把上面所有零件连起来的公交系统）。本期先不管它们。

一条最重要的工作流

你双击一个程序图标时，电脑做的事是：

# 双击图标的本质，一句话版 把程序文件从 硬盘 复制进 内存 → 让 CPU 从内存里逐条读取并执行

这一行的推论比它本身值钱得多：

  • 为什么要「加载」几秒？ 因为复制进内存需要时间，慢的那一端是硬盘。
  • 为什么关机再开要重新加载？ 因为内存断电就清空，程序本体只存在硬盘里。
  • 为什么内存满了会卡？ 因为内存装不下时，系统开始拿硬盘「客串」内存（叫虚拟内存），而硬盘比内存慢几百到上千倍 —— 相当于把草稿纸换成了仓库，每次打草稿都要跑一趟仓库。
  • 为什么加装内存条 / 换 SSD 是最有效的两笔升级？ 因为它们直接决定「排队」发生在哪里。
记住这张分工表

CPU 负责算，内存负责临时记，硬盘负责永久记。以后遇到任何「电脑为什么慢/卡/崩」，先问一句：是哪一环在排队？

02

速度体感：把 CPU 缩小成一个人

「内存比硬盘快几百倍」这种话听过就忘。换个说法你永远忘不掉： 假设 CPU 是一个人，它干一次活要 1 秒 —— 按同样的倍数放大，它找内存拿一次数据要等几分钟， 找硬盘要等好几天，访问一个网站要等好几年。点下面按钮感受一下：

TIME SCALER · CPU = 1 人
真实耗时 ≈ 0.3 纳秒（十亿分之 0.3 秒）
1 秒 · 眨一下眼的事
这是 CPU 的正常节奏：它快到大部分时间都在「等别人」。

换算基准：CPU 干一次活 ≈ 0.3 纳秒，把它放大成「1 秒」，其他部件按同一倍数放大。 这也是为什么 CPU 旁边要塞一层小小的「缓存」—— 把最常要的东西放在手边，省得每次都跑仓库。

由此得出的选购常识

同样预算下：内存 8G 换 16G 的体验提升，远大于 CPU i5 换 i7。因为对日常使用来说，瓶颈几乎总是内存和硬盘，而不是 CPU 的算力。广告总在吹 CPU 参数，但你日常卡顿，八成是内存满了。

顺带分清两个词：解释执行 vs 编译执行

上面第 4 站是 Python 的特色：边读边翻译边执行，像同声传译。 而 C、C++ 这类语言是先把整本书翻译完装订成册（编译成机器码），以后每次运行直接跑译文，所以更快，但换台电脑就得重新翻译。 你不需要背谁优谁劣，只要知道有三条路线存在：

方式代表语言类比特点
解释执行Python、JavaScript同声传译，说一句翻一句灵活、上手快，跑得慢一些
编译执行C、C++、Rust、Go先整本翻译再出版跑得飞快，改一行要重新编译
折中方案Java、C#先翻成统一中间稿，到处有人念「一次编译，到处运行」
一个反直觉的事实

你的代码在 CPU 眼里不是「代码」，只是数据。所谓运行程序，就是把一份特殊的数据从硬盘搬进内存，再让 CPU 按顺序处理它。所以「程序崩溃了」并不是什么神秘事件 —— 只是这份数据被执行到某一步时，遇到了它应付不了的情况。

04

实战：看懂任务管理器，给卡顿下诊断

「软件开发逻辑」最实用的入门课不在教科书里，在 Ctrl + Shift + Esc 打开的任务管理器里。 记住诊断思路：电脑同时只做四种事 —— 算（CPU）、临时记（内存）、读写（磁盘）、联网（网络）。 卡，就是其中一样在排队。对照下表：

症状谁在排队典型原因你能做的
风扇狂转，CPU 100%，机器烫CPU某个程序在死循环硬算（也可能是后台病毒/挖矿）按 CPU 排序，揪出占用最高的那个进程
内存占用 95% 以上，切窗口都卡内存开的东西太多，系统拿硬盘客串内存关掉不用的程序；长期如此就加内存条
磁盘 100% 但 CPU 很闲磁盘在等硬盘：大文件复制、杀毒扫描、老机械盘等它跑完；根治办法是换 SSD
硬件都正常，网页就是慢网络WiFi 信号、运营商、对方服务器这不是电脑的锅，重启路由器试试
开机后硬盘灯常亮几分钟磁盘系统更新、索引服务在后台读写不用管，让它们跑完

注意第一行和第三行的区别：CPU 100% 是「大脑算不过来」，磁盘 100% 是「仓库门口排长队」， 药方完全不同。网上七成「电脑卡怎么办」的文章说不清这一点，你现在比它们都清楚。

三道自测

程序 A 内存泄漏，越跑越吃内存，最终电脑会怎样？

内存被吃满 → 系统开始用硬盘客串内存（虚拟内存）→ 一切突然变慢几十倍，硬盘灯常亮 → 最坏情况系统弹「内存不足」或直接把程序杀掉。所以「越用越卡、重启就好」的程序，十有八九是内存泄漏。

为什么把系统从机械硬盘换到 SSD，开机从 1 分钟变 10 秒？

开机 = 把大量系统文件从硬盘读进内存。机械硬盘寻道要十几毫秒（在人类尺度里是「一年」），SSD 随机读快百倍以上，排队时间直接消失。CPU 和内存没换，但瓶颈换了。

打开 30 个浏览器标签页，变卡的主因更可能是 CPU 还是内存？为什么？

内存。每个标签页都是一份活的数据要住在内存里（图片、网页状态），30 个标签轻松吃掉几个 GB。CPU 反而大部分时间在等 —— 网页静置时几乎不消耗算力。这也是为什么「标签页过多」的解法是关标签或加内存，而不是换 CPU。

AI 时代，爱好者要懂到什么程度

不用会写算法，不用背语法。但下面 5 个概念建议真懂 —— 它们是「看懂 AI 给你的代码」和「把 bug 说清楚」的地基。 每个概念一行代码就够：

概念人话版一行代码
变量贴了标签的盒子，东西放进去，贴纸换着用age = 20
函数自动贩卖机：投币（给参数）→ 出货（拿结果），里面怎么转不用管len("hello")
循环把无聊的重复事扔给电脑，它不会烦for i in range(3): print(i)
报错信息程序的求救信，从最后一行往上读，最后往往就一句人话Traceback ...
进程正在运行的程序；卡死了就杀掉，电脑不会坏任务管理器 → 结束任务
和 AI 协作的正确姿势

让 AI 写代码时，你的价值不在于亲自写出它，而在于描述得准：「我想要一个每次运行都往 记录.txt 追加一行时间的脚本」—— 这句话里的「追加」「每次运行」「txt 文件」全是这期教过的概念。 代码跑挂了，把报错的最后三行贴给 AI，比只说「它坏了」有用一百倍。

本周挑战：以观察为主，代码 ≤ 10 行

这周的挑战不考算法，考「亲眼看一次」。三级任选，做完任意一个都算赢。

Lv 1 · 观察 · 15 分钟 · 零代码

当一次电脑医生

  • 打开任务管理器（Ctrl+Shift+Esc），分别按 CPU / 内存 / 磁盘排序，记录前三名分别是谁。
  • 开着浏览器连开 15 个标签页，看内存涨了多少 GB。
  • 复制一个 1 GB 以上的大文件到另一个盘，同时观察：磁盘是不是冲到 100%？CPU 当时是多少？
  • 把三个观察写成三句话（例如「我电脑最吃内存的是微信」）。
Lv 2 · 动手 · 20 分钟 · 代码 10 行

亲手证明「内存比硬盘快几百倍」

  • 跑下面这段 10 行 Python 脚本：分别测「往内存里塞 100 万个数」和「往硬盘写 100 万行」的耗时。
  • 记录两个数字，算出比值。
  • 和第 02 节的时间体感表对照，看你实测的倍数落在哪个区间。

认领你自己的硬件

  • 查出你这台电脑的 CPU 型号 / 内存容量 / 硬盘是固态还是机械（Windows：设置 → 系统 → 关于）。
  • 对照第 01 节的分工表，写一句话判断：你这台机器日常的瓶颈最可能是哪一环？依据是什么？
  • 进阶（可选）：搜你的 CPU 型号 + 「天梯图」，看看它排在什么位置。

Lv2 的 10 行脚本（直接复制运行）

# memory_vs_disk.py —— 亲口问问你的电脑：内存和硬盘差多少倍？ import time N = 1_000_000 t0 = time.time(); data = [0] * N; t1 = time.time() # ① 写内存 print(f"写内存 100 万个数：{t1-t0:.3f} 秒") t0 = time.time() with open("test.txt", "w") as f: # ② 写硬盘 for i in range(N): f.write(f"{i}\n") t1 = time.time() print(f"写硬盘 100 万行：{t1-t0:.3f} 秒")

带走三句话

  1. 电脑 = 大脑（CPU）+ 草稿纸（内存）+ 仓库（硬盘）。所有「慢、卡、崩」都是这三样之一在排队，先问是哪一环，再谈解决办法。
  2. 运行程序 = 把代码当数据搬运。双击图标，本质是把文件从硬盘复制进内存让 CPU 逐条执行；内存断电清空，所以一切都要「重新加载」。
  3. AI 时代爱好者的核心竞争力是「说得清」。懂分工、会看排队、能读报错最后一行 —— 这三件事让你把 AI 用得比别人好得多。
