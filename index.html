02 Week 02 · How Sites Store Your Password

你的密码，网站到底怎么存的？

每次注册，你都把一串只有自己知道的字符，交给了一个从没见过面的人保管。 那么在他的数据库里，你交出去的东西长什么样？如果那就是 hunter2 本身， 下一次数据库被人拖走，你的密码就会出现在某个论坛的截图里。 这期我们把「服务器那一端」翻过来看：它存的其实是一串谁也还原不了的指纹 —— 中间有三个坑，每个坑都真实地让几亿人裸奔过。

00

先把问题问清楚

你注册一个网站，填了邮箱和密码，点「注册」。接下来在服务器那边，有一张表多了一行。 那一行里到底写了什么？

最省事的写法当然是原样记下来：zhangsan@example.com | hunter2。 代码两行就能跑通，登录时拿出来一比就行。但这么做的后果是： 任何能碰到这张表的人，都能直接读到你的密码 —— 写这套系统的程序员、运维、外包公司、 以及任何一个把数据库偷走的人。

所以从几十年前开始，正经的做法就只有一条：

本期的唯一核心句

网站不存你的密码，只存一串由密码算出来的指纹。指纹能核对、不能还原 —— 所以连网站自己也不知道你的密码是什么。

这句话听着像技术细节，其实推得出很多你天天遇到的现象。这期讲完，下面这些问题你都会有确定的答案：

  • 为什么几乎所有网站只能让你「重置密码」，而不能「把原密码发给你」？
  • 客服说「我帮你查一下你原来的密码」—— 这句话为什么应该让你立刻警惕？
  • 地址栏那个小锁（HTTPS）到底保护了什么？它保护不了什么？
  • 为什么「每 90 天必须改密码、必须有大写和符号」这套规矩，现在被官方建议取消了？
你以为你在设密码，其实你在向一个陌生人交付一个「只能核对、不能反读」的凭证。
01

指纹机：把任意文字压成一串固定长度的乱码

承担这个任务的工具叫哈希函数（hash function）。最好的类比是一台绞肉机： 肉放进去，出来的是香肠；香肠永远变不回肉。

这台机器的规矩是固定的：同一份输入，永远得到同一份输出。 所以网站可以这样用 —— 注册时算一次存起来，登录时拿你的输入再算一次，两次结果一样，就说明你输入的密码一样。 全程它都不需要知道你输的是什么。

下面这台机器是真的：它跑的是 SHA-256，和 Python 的 hashlib、和 Linux 的 sha256sum 算出来的是同一串字符。你现在就可以把讲义里的密码丢进去试。

SHA-256 · 指纹机（纯本地，不联网）
你输的内容 → 指纹（64 个十六进制字符）
末尾多打一个 ! → 指纹

橙色格子 = 和上面不一样的位置。试着把最后的 2 删掉、或者只加一个空格，看变化有多大。

你应该立刻注意到一件事：你只改了一个字符，下半张图几乎全变了。 这就是哈希的第二个脾气，它有个专门的名字叫雪崩效应（avalanche effect）—— 输入里翻动一片雪花，输出就像雪崩一样面目全非。刚才那个演示里，64 个字符中有 60 个左右会变。

它必须同时满足三条

性质人话解释如果没有它会怎样
定长 不管输入是 1 个字符还是 1 万字，输出永远是 64 个十六进制字符（256 位） 数据库得为「有人用了一篇论文当密码」留出巨大字段
单向 能从密码算出指纹，不能从指纹倒推密码 —— 因为这是「有损压缩」，原始信息已经丢了 偷到数据库就等于偷到所有明文密码
雪崩 输入变一个字符，输出变一大半 攻击者能靠「指纹有多像」猜出你的密码大概长什么样
注意一个用词陷阱

很多网站写「我们采用 MD5 加密存储密码」。加密和哈希是两件事： 加密是可逆的（有钥匙就能还原），哈希是不可逆的。把哈希说成加密，通常说明写这句话的人不太懂， 或者他在（不明智地）真的用了可逆的加密 —— 那意味着公司自己就能看到你的密码。两种都不是好信号。

02

顺着这三条，推出四个日常现象

理论讲完了，现在来收利息。上面那三条性质，每一条都能解释一个你遇到过但没想明白的现象。

推论一：网站没法「告诉你」原密码，只能让你重置

因为库里的指纹推不回密码。所以你点「忘记密码」时，收到的不是「您的密码是 hunter2」， 而是一个一次性重置链接。这不是网站小气，是它真的不知道。

反过来说：如果某个网站能把原密码发给你，它就是在明文存储或者可逆加密。 这不是方便，这是它整个安全体系已经塌了 —— 你该做的是去把这个密码在别处也改掉（因为你很可能到处用了同一个）。

推论二：「客服帮你查密码」是不能说的谎

同一个道理。真正的客服后台最多能看到「这个账号存在」「最近登录时间」「已绑定手机」， 看不到密码。任何声称能看到密码的系统，都把用户密码以一种可还原的形式存着了。

推论三：正因为它算不出你的密码，所以它可以安全地「比一比」

网站想提醒你「这个密码已经在公开泄露库里出现过」，怎么办？它可以只发你指纹的一小段去查， 对方回答「以这段开头的指纹有这些」，然后你在本地比对。全程对方不知道完整指纹，更不知道密码。 这就是 Have I Been Pwned 查密码时用的方法（叫 k-匿名）。 你可以现在就去试 —— 它是安全的，也是我这周挑战里的第一个任务。

推论四：从库里看不出你的密码有多长

因为定长。一个用 8 位密码的人和一个用 40 位密码的人，指纹都是 64 个字符。 这是个很实在的好处：泄露时攻击者不知道谁的密码值得优先硬啃。

所以「指纹」这个词要拆开看

指纹相似 = 密码相同；指纹不同 = 密码一定不同。它唯一能泄露的信息，就是「两个账号是不是同一个密码」。 这也是为什么你在同一个网站改密码时，系统会拦你「新密码不能和旧密码相同」—— 它只要比一下指纹就知道。

03

第一个坑：只存指纹，等于白干

假设某个网站做对了上一节：只存指纹。它安全了吗？没有。因为指纹有一个致命的特点： 同一个密码，指纹永远一模一样。

这意味着攻击者根本不需要「破解」任何东西。他只要提前算好一张巨大的对照表 —— 常见密码 → 对应的指纹，几亿行 —— 然后把偷来的指纹往里一扔，对上的那一行就写着明文。 这张表叫彩虹表。而"常见密码"的分布极度集中：全球每年泄露的密码统计里，前十名永远是 123456、password、qwerty 这些。也就是说，偷来一千万条指纹，几秒钟就能还原出其中几百万条。

更糟的是第二个问题：能一次破一片。如果一百万个用户都用 123456， 他们的指纹全都一样，破解一条等于破解一百万个。

解药：给每个人撒一把不同的盐

做法简单到有点好笑：注册的时候，随机生成一小段字符（比如 16 个十六进制的乱码），叫盐（salt）。 算指纹的时候先拼上盐：算的不是 密码 的指纹，而是 盐 + 密码 的指纹。 然后把盐和指纹一起明文存进数据库。

# 两种存法的区别，就一行 不加盐： 存 sha256( 密码 ) ← 同一密码，全球指纹都一样 加盐： 存 盐 + sha256( 盐 + 密码 ) ← 同一密码，每个账号指纹都不同 登录时： 拿出来 → 用库里的盐重算一次 → 和库里的指纹比 → 一样就放行

同一个密码，每次注册指纹都完全不同 →
攻击者必须一个账号一个账号单独啃。

左栏那张小表只有 6 行。真实的彩虹表有几亿行，你的密码只要在「全球最常见的 100 万个密码」里，就等于没设。

盐为什么有用？因为盐不需要保密。它的作用不是「藏起来」，而是打散： 让每个账号的指纹都独一无二，从而让你提前算好的表一次性全部作废。 攻击者面对一千万条指纹，只能一条一条单独试，成本从「算一次」变成「算一千万次」。

但是，盐救不了弱密码

这句话很重要，很多人被「加盐」这个词骗了。如果你的密码是 123456，加了盐也只是让攻击者多花几毫秒 —— 他试着把 123456 拼上你的盐算一遍，一比对，中了。盐防的是「批量」和「查表」，防不了「你的密码本身太好猜」。 防弱密码是另一套机制（第 06 节讲的那几条），别指望盐代劳。

04

第二个坑：指纹算得太快了

现在攻击者没法查表了，只能老老实实一个个试。那他试得有多快？

SHA-256 的设计目标是快 —— 它本来是用来校验文件完整性的，工程师花了大力气让它一秒能算几十亿次。 这对存密码来说正好是灾难：一块高端显卡每秒能试几十亿到上百亿个候选密码。

算一笔账你就懂了。8 位小写字母一共有 26⁸ ≈ 2088 亿种组合，听着很多吧？ 在这个速度下，几分钟就试完了。

解药：故意把它做慢

于是有人反着来：既然攻击者的唯一武器是「快」，那我们就发明专门用来慢的哈希。 这类函数（最常用的是 bcrypt，新的还有 scrypt 和 argon2）算一次要 0.05 ~ 0.5 秒， 而且「慢多少」是可以调的 —— 电脑变快了，就把参数调高一档，让它永远慢在人类能忍、机器受不了的区间。

SHA-256bcrypt（成本 12）
算一次的时间约 0.00000003 秒约 0.25 秒
你登录时的感受毫无感觉毫无感觉
攻击者一天能试约 8.6 万亿次约 35 万次
设计目标尽快算完尽量算不完

看最后两行：同一台机器，攻击速度差了两千五百万倍。而对正常用户来说，两者都是「输完密码，页面跳一下」—— 你根本察觉不到 0.25 秒。这就是设计者的巧思：把成本全部转移给攻击者。

05

把三件常被混为一谈的事分开

讲到这里，很多人会把三个东西搅在一起：HTTPS、哈希、加密。它们解决的是完全不同的问题， 分清楚了，你看安全新闻就不会被人牵着走。

机制保护哪一段防谁能还原吗
HTTPS（地址栏的小锁） 你的浏览器 → 网站服务器，这一段路上 同一个 WiFi 下的陌生人、运营商、蹭网的路由器 不涉及 —— 它只是把包裹封起来
哈希 + 盐 + 慢哈希 网站服务器内部，数据库里 偷走数据库的人、内部员工 不能（这就是全部意义）
加密（对称/非对称） 任何需要以后还能读出来的数据 没有钥匙的人 能，有钥匙就行

看清楚这张表，你就能拆掉两个很常见的误解：

误解一：「有绿锁，说明这网站靠谱」

小锁只保证你和它之间的对话没被第三方偷听。它完全不保证这家公司怎么存你的密码、 会不会把你的数据卖给第三方、跑路时会不会带走你的信息。 一个钓鱼网站同样可以申请到证书、挂上小锁 —— 它保护的是「骗子和你之间的通信」，一点没帮到你。

误解二：「密码是加密存储的，很安全」

如果真的是「加密」（可逆），那公司自己就能解出来 —— 也就意味着任何能进后台的人都能解出来， 任何拿到钥匙的人都能解出来。密码不该是能被还原的东西，这也是为什么第 01 节强调「哈希不是加密」。

所以「忘记密码」的邮件里没有密码

它给的是一串带时效的随机链接。点开 → 验证是你本人 → 让你设一个新的。 整条链路里，密码从头到尾只在你自己的设备上存在过一瞬间，服务器从来没有「知道」过它。

06

那你到底该怎么设密码

前面讲的都是网站的责任。但有一半的风险在你手上 —— 因为大部分账号被盗，不是因为网站被黑，而是因为同一个密码在另一个被黑的网站上用过。 这叫撞库：攻击者拿着一份泄露的「邮箱 + 密码」清单，去几百个网站挨个试。 你在一家小论坛用过和大厂邮箱一样的密码，那家论坛被拖库的那天，你的邮箱就危险了。

四条真正有用的建议

做法为什么它有用
1. 长度优先
12 位以上，最好是一句话		长度是唯一按指数增长的因素。一句话天然又长又好记。
2. 一个都不重复
尤其是邮箱、银行、微信		撞库的全部威力都建立在「复用」上。不重复，一次泄露就只损失一个站。
3. 用密码管理器
浏览器自带 / 1Password / Bitwarden		「记不住」不是你的问题，是设计问题。让机器记随机长串，你只需记住一个主密码。
4. 开二次验证
短信验证码也算，验证器 App 更好		这是唯一能在「密码已经泄露」之后还救你的东西。优先级高于换更复杂的密码。
两条已经过时的建议，可以不用听了

① 「必须含大写、数字、符号」 —— 它逼出来的结果就是 Password1! 这种人人都会想到的变形， 反而更好猜。美国国家标准与技术研究院（NIST）现在的建议是：不强制组合规则，只要求足够长。
② 「每 90 天必须换密码」 —— 它逼出来的结果是 abc123 → abc124。 现在的建议是：只在怀疑泄露时换。

关于「浏览器帮我记住密码」

这个其实比你想的安全：浏览器存的是用你系统账户钥匙加密过的本地文件，别人拿到你电脑也需要你的登录密码才能解开。 真正的风险不是「浏览器记住」，而是你把同一个密码手动输进了所有网站。 相比之下，用浏览器或密码管理器生成一堆互不相同的随机串，安全性高得多 —— 唯一的代价是你要信任这台设备，所以电脑别裸奔、手机记得锁屏。

三道自测

网站被拖库了，但它用了「加盐 + bcrypt」，攻击者拿到了什么？

一堆「盐 + 指纹」。他不能直接读出密码，也没法查表（盐打散了）。他能做的只有一件事：针对每个账号单独硬猜，而 bcrypt 让每次猜都要 0.25 秒。如果密码本身够强，几万年也猜不出来；如果密码是 123456，那第一批就中。所以「加盐 + 慢哈希」的意义是：把损失从「全军覆没」缩小到「弱密码的那部分人」，而不是零损失。

为什么同一个密码，在 A 网站泄露了，B 网站也可能跟着完蛋？

因为密码复用。A 站被拖库后，攻击者拿到「你的邮箱 + 明文密码」（A 站可能没做好），直接拿去 B 站登录试试 —— 这叫撞库，是账号被盗最主要的原因，比「黑客专门针对你」常见得多。这也是为什么「不重复」比「复杂」更重要。

我开了短信二次验证，密码是不是可以随便设了？

不行，但优先级确实变了。二次验证能挡住「别人拿你泄露的密码来登录」，却挡不住「别人用你的密码做别的事」以及「短信被劫持」。正确顺序是：先开二次验证（收益最大），再换成长且不重复的密码。两件事都做，成本也就十分钟。

亲手验证「加盐」和「雪崩」

  • 把仓库里的 week-02/salt_demo.py 存到本地，运行 python salt_demo.py（不需要装任何东西）。
  • 看输出里的第一段：同一个密码注册两次，两个指纹完全不同 —— 这就是盐。
  • 改脚本里 pw 的值，换成你自己的某个密码的变体（比如把最后一个字母改掉），再跑一次，看 64 个字符变了几个。
  • 进阶：用网页版的指纹机算一次，再用脚本算一次，确认两边的结果一模一样 —— 这说明它们用的是同一台「绞肉机」。

Lv2 的核心代码（就这几行）

# 从 salt_demo.py 里摘出来的骨架 —— 网站真正干的事 import hashlib, secrets def fingerprint(text): return hashlib.sha256(text.encode()).hexdigest() # 64 个字符的指纹 salt = secrets.token_hex(8) # 每个账号一份随机盐 stored = fingerprint(salt + "你的密码") # 库里存的是这个 # 登录时：fingerprint(salt + 用户输入) == stored → 放行

真实项目请把 sha256 换成 bcrypt 或 argon2 —— 原因见第 04 节。

去仓库开一个 Issue，标题写「Week02 打卡」，正文贴你的三句话 / 两条指纹对比 / 长辈体检记。 记住那条硬规矩：永远不要贴真实密码，只贴结构和指纹（指纹是安全的，它反推不出密码）。

08

带走三句话

  1. 网站存的是指纹，不是密码。所以它只能让你重置、不能把原密码发给你 —— 谁能发给你，谁的库就是明文。
  2. 光有指纹还不够，得加盐、还得慢。盐让每个人的指纹独一无二（防查表），慢哈希让硬猜变得不划算（防暴力）。但这两样都救不了「密码本身太好猜」。
  3. 你的风险一半在自己手上。不重复 > 够长 > 花哨，二次验证 > 一切。花十分钟开二次验证，比把密码从 8 位改成 12 位有用得多。
