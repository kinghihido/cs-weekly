## 第 01 期速览：布隆过滤器

**一句话**：一个位数组 + k 个哈希函数构成的概率型集合，查询返回"一定不在"或"可能在"，永不产生假阴性。

**核心公式**（这一行是整个学科的浓缩）：

```
误判率   p ≈ (1 − e^(−kn/m))^k
最优哈希 k* = (m/n) · ln2 ≈ 0.693 · (m/n)
所需空间 m/n = −ln(p) / (ln2)² ≈ 1.44 · log₂(1/p)
```

**参数直觉**：1% 误判率 → 每元素 9.6 bit + 7 个哈希；10 亿 URL 去重只需要约 1.2 GB，而哈希表要 60 GB 以上。

**为什么不会漏判**：位只会 `0 → 1`，永不清零。插入时点亮的 k 位永远亮着，所以再查必然全中。假阴性只可能来自"删除"或并发覆盖这类破坏单调性的实现 bug。

**工程坑**：容量必须事先估（超载 2 倍误判率就崩）、不能用语言内置 `hash()`（进程间不稳定）、k 超过最优值反而更差。
