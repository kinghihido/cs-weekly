# Week 02 讲义 · 你的密码，网站到底怎么存的

## 00 · 先把问题问清楚

你注册一个网站，填了邮箱和密码，点「注册」。服务器那边的数据库里，多了一行。
**那一行里到底写了什么？**

最省事的写法是原样记下来：`zhangsan@example.com | hunter2`。两行代码就能跑通。
但后果是：**任何能碰到这张表的人，都能直接读到你的密码** —— 程序员、运维、外包、以及偷走数据库的人。

所以正经的做法只有一条，也是本期的唯一核心句：

> **网站不存你的密码，只存一串由密码算出来的「指纹」。指纹能核对、不能还原 —— 连网站自己也不知道你的密码是什么。**

---

## 01 · 指纹机：把任意文字压成一串固定长度的乱码

承担这个任务的工具叫**哈希函数**（hash function）。最好的类比是一台**绞肉机**：
肉放进去，出来的是香肠；香肠永远变不回肉。它的规矩是：**同一份输入，永远得到同一份输出**。

所以网站可以这样用：注册时算一次存起来；登录时拿你的输入**再算一次**，两次结果一样，就说明密码一样。全程它不需要知道你输的是什么。

讲义网页里的指纹机跑的是**真实的 SHA-256**（和 Python `hashlib`、Linux `sha256sum` 结果完全一致）。以 `hunter2` 为例：

```
hunter2  →  f52fbd32b2b3b86ff88ef6c490628285f482af15ddcb29541f94bcf526a3f6c7
hunter3  →  fb8c2e2b85ca81eb4350199faddd983cb26af3064614e737ea9f479621cfa57a
```

只改了最后一个字符，64 个字符里 61 个变了 —— 这叫**雪崩效应**。

它必须同时满足三条：

| 性质 | 人话解释 | 如果没有它会怎样 |
| --- | --- | --- |
| **定长** | 输入 1 个字或 1 万字，输出永远是 64 个十六进制字符（256 位） | 数据库得为「有人用一篇论文当密码」留出巨大字段 |
| **单向** | 能从密码算出指纹，不能反推 —— 因为这是有损压缩，原始信息已经丢了 | 偷到数据库等于偷到所有明文密码 |
| **雪崩** | 输入变一个字符，输出变一大半 | 攻击者能靠「指纹有多像」猜你的密码 |

**用词陷阱**：很多网站说「我们采用 MD5 **加密**存储密码」。
加密是*可逆*的（有钥匙就能还原），哈希是*不可逆*的。把哈希说成加密，通常说明写这句话的人不懂，或者他真的用了可逆加密 —— 那意味着公司自己能看到你的密码。两种都不是好信号。

## 02 · 顺着这三条，推出四个日常现象

1. **网站没法「告诉你」原密码，只能让你重置。**
   库里的指纹推不回密码，所以「忘记密码」收到的是一次性重置链接，不是「您的密码是 hunter2」。
2. **「客服帮你查原密码」是不能说的谎。**
   真正的后台看不到密码。任何声称能查到原密码的系统，都以可还原的形式存了密码 —— 这是危险信号。
3. **正因为它算不出密码，才能安全地「比一比」。**
   泄露库查询服务（如 Have I Been Pwned）只上传指纹的一小段去比对，对方全程不知道完整指纹，更不知道密码（这叫 k-匿名）。
4. **从库里看不出密码有多长。**
   因为定长。8 位和 40 位密码的指纹都是 64 个字符，泄露时攻击者不知道谁的密码值得优先硬啃。

指纹唯一能泄露的信息是「两个账号是不是同一个密码」—— 所以网站能拦你「新密码不能和旧密码相同」，只要比一下指纹就知道。

---

## 03 · 第一个坑：只存指纹，等于白干

指纹有个致命特点：**同一个密码，指纹永远一模一样**。攻击者根本不需要「破解」——
他提前算好一张几亿行的对照表（常见密码 → 指纹），把偷来的指纹往里一扔，对上的那行就写着明文。
这张表叫**彩虹表**。而人类选密码的分布极度集中，前十名永远是 `123456`、`password`、`qwerty`。

更糟的是：一百万个用 `123456` 的人，指纹全都一样，**破一条等于破一百万条**。

### 解药：给每个人撒一把不同的盐

注册时随机生成一小段字符（**盐**，salt），算指纹时先拼上：

```
不加盐： 存  sha256( 密码 )               ← 同一密码，全球指纹都一样
加  盐： 存  盐 + sha256( 盐 + 密码 )      ← 同一密码，每个账号指纹都不同

登录时： 取出库里的盐 → 重算一遍 → 和库里的指纹比 → 一样就放行
```

**盐不需要保密**，和指纹一起明文存就行。它的作用不是「藏」，而是「打散」：
让每个账号的指纹独一无二，让提前算好的表**一次性全部作废**，攻击者只能一个账号一个账号单独啃。

> ⚠️ **但盐救不了弱密码。** 密码是 `123456`，加了盐攻击者也只是多花几毫秒拼一下。
> 盐防的是「批量」和「查表」，防不了「密码本身太好猜」。

## 04 · 第二个坑：指纹算得太快了

SHA-256 的设计目标是**快**（它本来是校验文件用的）。一块高端显卡每秒能试**几十亿到上百亿**个候选密码。
**8 位小写字母**共 26⁸ ≈ 2088 亿种组合 —— **几分钟就试完了**。

于是有了反着来的设计：**专门用来慢的哈希** —— bcrypt（以及更新的 scrypt、argon2）。
每次计算要 0.05~0.5 秒，「慢多少」可以调参数，电脑变快了就调高一档。

| | SHA-256 | bcrypt（成本 12） |
| --- | --- | --- |
| 算一次的时间 | 约 0.00000003 秒 | 约 0.25 秒 |
| 你登录时的感受 | 毫无感觉 | 毫无感觉 |
| 攻击者一天能试 | 约 8.6 万亿次 | 约 35 万次 |

同一台机器，攻击速度差**两千五百万倍**，而你完全察觉不到 0.25 秒。
设计者的巧思就一句话：**把成本全部转移给攻击者。**

讲义里的「破解时间估算器」可以直观感受长度与字符集的影响。规律是：
**长度的影响是乘法级的，字符集的影响是加法级的** —— 先把长度堆够，再谈花哨。

注意估算的前提是密码**完全随机**。人挑的密码带名字、生日、键盘滑行，实际会快好几个数量级。

## 05 · 把三件常被混为一谈的事分开

| 机制 | 保护哪一段 | 防谁 | 能还原吗 |
| --- | --- | --- | --- |
| **HTTPS**（地址栏小锁） | 浏览器 → 服务器这一段「路上」 | 同 WiFi 陌生人、运营商 | 不涉及，只是把包裹封起来 |
| **哈希 + 盐 + 慢哈希** | 服务器内部、数据库里 | 偷走数据库的人 | **不能**（这就是全部意义） |
| **加密** | 需要以后还能读出来的数据 | 没有钥匙的人 | **能**，有钥匙就行 |

两个常见误解：

- **「有绿锁说明网站靠谱」**：小锁只保证通信没被第三方偷听，完全不保证它内部怎么存、会不会卖你的数据。钓鱼网站同样可以挂上小锁。
- **「密码是加密存储的，很安全」**：真的加密意味着公司自己能解出来，也就意味着任何拿到钥匙的人都能解出来。密码不该是能被还原的东西。

## 06 · 那你到底该怎么设密码

大部分账号被盗不是因为网站被黑，而是**同一个密码在另一个被黑的网站上用过**（撞库）。

四条真正有用的建议：

1. **长度优先**：12 位以上，最好是一句话（中文短句也很好，不在英文词典里；但别用歌词诗句，语料库里都有）。
2. **一个都不重复**：尤其是邮箱、银行、微信。撞库的全部威力建立在「复用」上。
3. **用密码管理器**：浏览器自带 / 1Password / Bitwarden。「记不住」是设计问题，不是你的问题。
4. **开二次验证**：唯一能在「密码已泄露」后还救你的东西。**优先级高于换更复杂的密码。**

两条已经过时的建议（NIST 现行建议）：

- ❌ 「必须含大写、数字、符号」→ 逼出来的都是 `Password1!` 这种更好猜的变形。改为：**不强制组合，只要求足够长**。
- ❌ 「每 90 天必须换密码」→ 逼出来的都是 `abc123` → `abc124`。改为：**只在怀疑泄露时换**。

关于「浏览器记住密码」：比你想的安全 —— 它是用系统账户钥匙加密的本地文件。
真正的风险不是浏览器记住，而是**你把同一个密码手动输进了所有网站**。

## 08 · 带走三句话

1. **网站存的是指纹，不是密码。** 谁能把原密码发给你，谁的库就是明文。
2. **光有指纹不够，得加盐、还得慢。** 但这两样都救不了「密码本身太好猜」。
3. **你的风险一半在自己手上。** 不重复 > 够长 > 花哨；二次验证 > 一切。
